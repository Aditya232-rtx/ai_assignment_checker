## Professor workflow — `mca_labs` folder (start here)

Everything lives in **one OneDrive folder** named `mca_labs`:

```
OneDrive/
└── mca_labs/
    ├── MCA_EXP-2.docx, Mca_lab3_AJ_14.docx, ...   # student expt files (any names)
    ├── attendance.xlsx                             # rollno | lab1..lab11 (P/A)
    └── marks_mca_output.xlsx                       # generated by the pipeline
```

Run one command — the project **auto-finds** the folder, the attendance sheet,
grades with AI, applies the attendance rule, and writes the marks sheet back
into the same folder:

```bash
python3.11 -m checker.cli map-marks --subject mca --rubric rubrics/example_rubric.yaml
```

- `--subject mca` grades only files with "mca" in the name (skips everything else).
- Re-running picks up new submissions automatically (scan is stateless).
  Add `--interval 60` to re-run every 60s hands-free.
- Attendance rule per cell: not submitted → `0`; Present + submitted → AI score `/10`;
  Absent + submitted → capped at `5`.
- Rollno + experiment number are read from **inside the document** (tables included),
  so jumbled filenames are fine. `lab / expt / L3 / A5 / Exp6` styles all map.
- Overrides when needed: `--sync-path <dir> --attendance <file> --output <file>`.
  `ONEDRIVE_SYNC_PATH` / `MCA_LABS_NAME` env vars work too.

## Local AI Assignment Checker – Quick‑Start Guide

This pipeline **does not talk to Microsoft Graph or any cloud service**.  Teachers sync the SharePoint "Student Work" folder to their local machine with the OneDrive desktop client.  The script then watches (or batch‑processes) that folder, grades each submission with a local LLM via Ollama, and writes a tidy CSV that can be copy‑pasted into Teams.

### 1️⃣ Prerequisites
- **Python 3.11+** (installed from python.org or via Homebrew/conda).
- **Ollama** with a model that can follow JSON instructions, e.g. `ollama pull llama3:8b`.
- **OneDrive desktop client** configured to sync the class "Student Work" folder to a local directory.
- (Optional) `pdftotext` (poppler) and `docx2txt` for PDF/DOCX parsing – install via Homebrew: `brew install poppler && pip install docx2txt`.

### 2️⃣ Clone this repo and set up a virtual environment
```bash
git clone <repo‑url> ai-assignment-checker-local
cd ai-assignment-checker-local
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt  # see below for needed packages
```

### 3️⃣ Configuration (environment variables)
Create a `.env` file **or export** these variables in your shell:
```
# Ollama connection (defaults work for a local install)
OLLAMA_URL=http://localhost:11434
MODEL_NAME=llama3:8b

# Absolute path where OneDrive syncs the "Student Work" folder.
# Example on macOS: /Users/<you>/OneDrive – ClassName/Student Work
ONEDRIVE_SYNC_PATH=/Users/you/OneDrive/YourClass/Student Work

# Where the final CSV will live (default inside the repo data folder)
OUTPUT_CSV_PATH=$(pwd)/data/grades_output.csv

# Flags – keep true for safe development; set false for production runs.
DRY_RUN=true          # never write to Teams (no network in this version)
RETAIN_RAW=true      # keep the original file after parsing (set false to delete)
```
The code reads these variables at runtime, so you can change them without editing Python files.

### 4️⃣ Initialise the SQLite tracking DB
```bash
python -c "from checker.db import init_db; init_db()"
```
This creates `data/grading.db` with a table that remembers which files have been processed.

### 5️⃣ Prepare a few dummy submissions for testing
Create a folder structure that mimics OneDrive sync, e.g.:
```bash
mkdir -p data/student_work
# Dummy files – name pattern `<studentId>_assignment.ext`
cat <<EOF > data/student_work/alice_essay.txt
Alice's essay about the importance of testing.
EOF
cat <<EOF > data/student_work/bob_code.py
# Bob's simple script
print("Hello World")
EOF
cat <<EOF > data/student_work/carol_report.pdf
# (use any small PDF; you can convert the txt above with LibreOffice)
EOF
```
Make sure the `ONEDRIVE_SYNC_PATH` env var points to `$(pwd)/data/student_work`.

### 6️⃣ Run the *discover* step to see what the ingestor finds
```bash
python - <<'PY'
from checker.local_ingestor import list_pending_files
print(list_pending_files())
PY
```
You should see a list of the three dummy files with status `new`.

### 7️⃣ Run the full grading pipeline (batch mode)
```bash
python checker/cli.py grade-all --rubric rubrics/example_rubric.yaml
```
- The script parses each file, runs pre‑checks, calls the grader and verifier agents via Ollama, and finally appends a line to `grades_output.csv`.
- Because `DRY_RUN` is `true` by default, no external side‑effects occur.

### 8️⃣ Verify the CSV output
```bash
cat data/grades_output.csv
```
You should see rows like:
```
student_id,total_score,feedback
alice,8,"Clarity: 4/5 – good intro …"
bob,6,"Correctness: 5/5 – works as expected …"
carol,7,"Presentation: 3/5 – layout could improve …"
```
(Exact numbers depend on your rubric and LLM output.)

### 9️⃣ Re‑run the script – it should **skip** already‑graded files
```bash
python checker/cli.py grade-all --rubric rubrics/example_rubric.yaml
```
The console will report `0 new submissions` and the CSV will stay unchanged.

### 📦 `requirements.txt`

Add any additional packages (e.g. `docx2txt`, `pandas` for CSV handling) as you develop further.
